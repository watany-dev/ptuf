# Releasing

`ptuf` ships pre-built binaries via [cargo-dist] and publishes the crate to
[crates.io]. A release is triggered by pushing a Git tag of the form `vX.Y.Z`.

[cargo-dist]: https://opensource.axo.dev/cargo-dist/
[crates.io]: https://crates.io/crates/ptuf

## One-time setup

1. **`CRATES_IO_TOKEN`** — create a scoped publish token at
   <https://crates.io/me> and add it as a GitHub Actions secret on the
   `watany-dev/ptuf` repository. The crate must already be reserved by an
   initial manual `cargo publish`, or the first tagged release will create it.
2. The three release workflows live at:
   - `.github/workflows/release.yml` (cargo-dist, regenerated by `dist generate`)
   - `.github/workflows/publish-crates.yml` (hand-written, NOT regenerated)
   - `.github/workflows/release-verify.yml` (hand-written, NOT regenerated;
     attaches `SHA256SUMS`, SPDX SBOM, and Build Provenance Attestation)

## Cutting a release

1. Make sure `main` is green (`make check`).
2. Bump the version:
   - `Cargo.toml` `[package].version`
   - `Cargo.lock` (run `cargo build` to refresh, commit the diff)
3. Update `CHANGELOG.md`:
   - Move items from `[Unreleased]` into a new `## [X.Y.Z] - YYYY-MM-DD` section.
   - Add the new compare/release links at the bottom.
4. Commit:

   ```bash
   git commit -am "release: vX.Y.Z"
   ```

5. Tag and push:

   ```bash
   git tag vX.Y.Z
   git push origin main
   git push origin vX.Y.Z
   ```

6. Watch GitHub Actions:
   - `Release` workflow builds 6 platforms, creates a GitHub Release, attaches
     archives + per-archive `.sha256` + `ptuf-installer.sh` +
     `ptuf-installer.ps1`.
   - On `release: published`, two sibling workflows run in parallel:
     - `Release Verify` aggregates `SHA256SUMS`, generates the SPDX SBOM
       (`ptuf-<tag>.spdx.json`), and issues GitHub Build Provenance and
       SBOM attestations on every archive. Attached assets typically appear
       within ~3 minutes of the release going live.
     - `Publish to crates.io` runs `cargo publish` (skipped automatically
       for prereleases).

7. Smoke-test post-release using the verified-install path
   (`README.md` → "Verified install"):

   ```bash
   VERSION=vX.Y.Z TARGET=x86_64-unknown-linux-musl
   BASE="https://github.com/watany-dev/ptuf/releases/download/${VERSION}"
   curl -LO "${BASE}/ptuf-${TARGET}.tar.gz"
   curl -LO "${BASE}/SHA256SUMS"
   sha256sum --ignore-missing -c SHA256SUMS
   gh attestation verify "ptuf-${TARGET}.tar.gz" --owner watany-dev
   tar -xzf "ptuf-${TARGET}.tar.gz"
   "./ptuf-${TARGET}/ptuf" --version
   ```

   And separately:

   ```bash
   cargo install ptuf
   ```

## Pre-releases

Tags like `v0.1.0-rc.1` are accepted. They produce a GitHub Release marked as
`prerelease`, and `publish-crates.yml` skips them via
`!github.event.release.prerelease`.

## Regenerating the release workflow

Whenever you bump cargo-dist or change `dist-workspace.toml`:

```bash
dist generate
```

This rewrites `.github/workflows/release.yml`. Do **not** hand-edit that file —
keep release.yml under cargo-dist control and put any custom CI in
`publish-crates.yml` or sibling workflows.

The matrix in `release.yml` is computed dynamically from `dist plan`, so
adding or removing entries in `targets = [...]` does **not** require
regenerating the workflow on its own — but bumping `cargo-dist-version`
or other structural keys does.

## Editing release-verify.yml

`release-verify.yml` is **hand-written** and **not** under cargo-dist
control. It is in scope for zizmor's full audit (no entries in
`.github/zizmor.yml` `ignore:` lists). When editing it:

- Funnel `github.event.*` and `github.ref_name` through `env:` instead of
  inline `${{ }}` in `run:` blocks (template-injection guard).
- SHA-pin every third-party action; dependabot's `github-actions`
  ecosystem updates them weekly.
- Keep `gh release upload --clobber` to make re-runs idempotent.

When updating action SHAs, cross-reference each tag against the upstream
release page to confirm the SHA still resolves to the intended tag.

## Why `lld` is in the apt deps

`.cargo/config.toml` pins the linker for `x86_64-unknown-linux-gnu` to `lld`
for fast local Linux builds. `dist-workspace.toml` mirrors that as
`[dist.dependencies.apt] lld = "*"` so the GitHub Linux runners install it
before invoking `cargo build`. The same dep is installed in
`publish-crates.yml` for the `cargo publish` verify step.
