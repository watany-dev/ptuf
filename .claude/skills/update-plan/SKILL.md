# update-plan スキル

ptuf の plan モード完了直前に、プランファイルの完成度を担保するための 4 フェーズ。

## Phase 1: コンテキスト収集

- 現在のプランファイルを読み込む
- `docs/design/` の関連設計書、`README.md`、`CLAUDE.md`、`Cargo.toml` を読む
- プランが影響する `src/` 配下のファイルを読む

## Phase 2: プラン品質評価 (100 点満点 / 5 カテゴリ)

`update-design` と同じ 5 カテゴリで採点する。合格ライン 90 点。

| カテゴリ | 観点 |
| --- | --- |
| モジュール / 構造体設計 | プランで触れる Rust 構造体・関数の境界の明確さ |
| フック契約 | PreToolUse 入出力の互換維持、変更箇所の影響範囲 |
| 判定ルール / ポリシー | 拒否ロジックの方針、デフォルト挙動への影響 |
| エラーハンドリング | `Result` 伝搬、`unwrap` 禁止、終了コード規約の維持 |
| テスト容易性 | 95% coverage 維持の戦略、テスト追加箇所の具体性 |

## Phase 3: 整合性チェック

- プラン ↔ 既存 `src/` の整合（参照しているシンボル名・パスが実在するか）
- プラン ↔ 既存設計書の整合
- プラン内部の段階分け順序の妥当性（依存関係の前後）

## Phase 4: プラン改善と出力

- 検出した問題を P0 / P1 / P2 に分類してプランへ反映
- 末尾に **検証サマリ** を追記（点数表 + 主要所見）
- 最後に `ExitPlanMode` を呼んでユーザーに提示する

## 実行タイミング

プランファイル書き出しが終わった直後、`ExitPlanMode` 呼び出し直前に発動する。
